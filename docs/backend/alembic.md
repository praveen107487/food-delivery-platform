# Migrations with Alembic

## Purpose

This document explains how the Food Delivery Platform manages database schema changes using **Alembic** and **SQLAlchemy**. It serves as a reference for contributors and describes the migration workflow, project conventions, and operational guidelines.

---

## Scope

This module covers:

* Alembic configuration
* SQLAlchemy metadata integration
* Migration generation
* Schema version tracking
* Upgrade and downgrade procedures
* Migration review process
* Production migration strategy

---

## Architecture

```text
SQLAlchemy ORM Models
          │
          ▼
SQLAlchemy Metadata
          │
          ▼
Alembic Autogeneration
          │
          ▼
Migration Revisions
          │
          ▼
PostgreSQL Database
```

---

## Project Conventions

* SQLAlchemy ORM models are the authoritative schema definition.
* Alembic migrations are generated from model changes.
* Every autogenerated migration must be reviewed before execution.
* Migration files are committed to version control.
* Applied migration files are immutable; corrections are introduced through new revisions.
* Model changes and their corresponding migration should be committed together.

---

## Standard Migration Workflow

```text
Update ORM Models
        │
        ▼
Generate Migration
        │
        ▼
Review Migration
        │
        ▼
Execute Upgrade
        │
        ▼
Verify Schema
        │
        ▼
Commit Changes
```

---

## Operational Guidelines

* Never modify the database schema manually in development, staging, or production.
* Keep each migration focused on a single logical schema change.
* Test both `upgrade()` and `downgrade()` during development.
* Preserve the complete migration history to ensure reproducible deployments.
